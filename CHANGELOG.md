## [v0.2.0] - 2026-10-26

### Highlights

- `petstore-server` serves every operation of the Petstore OpenAPI definition from memory, so there is a real Swagger Petstore to call
- The server can be an AAuth resource (`--auth aauth`): each operation requires the access its `x-aauth` annotation names, from the agent's identity to the person's approval of a scope
- The OpenAPI definition is embedded in package `petstore`, with an `x-aauth` annotation on every operation
- A static container image runs the server, with a built-in health check
- The MySQL tools read their databases from a JSON file named by `PETSTORE_DATASOURCES` instead of an untracked source file, so a clean clone builds

### Security

- `create_tables` no longer prints the database password ([`7dc3a35`](https://github.com/grokify/petstore/commit/7dc3a35))
- Database hostnames and credentials come from a private file outside the repository, never from source ([`8c58d2e`](https://github.com/grokify/petstore/commit/8c58d2e))
- The upload handler's multipart parse is bounded by `http.MaxBytesReader`; the lint suppression says so ([`e0b7d4d`](https://github.com/grokify/petstore/commit/e0b7d4d))
